# Version 0.2.0

**Release Date**: November 13, 2026

## Added

- **New API Support**: OpenCNPJ integration
  - Free API with monthly updated database
  - Full download option available
  - Complete data normalization support
- OpenCNPJ added to API selection dropdown
- OpenCNPJ added to automatic fallback chain
- **Alphanumeric CNPJ support**: new CNPJs issued by Receita Federal since July 31, 2026 (letters in the first 12 characters, numeric check digits) are accepted. Input is upper-cased and the mask (`.`, `/`, `-`, spaces) is removed; letters are kept.
- **Check-digit validation** for numeric and alphanumeric CNPJs (each character = ASCII code − 48, modulo 11). Invalid CNPJs fail immediately, without calling any API.

## Changed

- Updated project description from 5 to 6 supported APIs
- Improved API descriptions in documentation
- BrasilAPI correctly labeled as "Community" project instead of "Official"
- **Request Delay is now a per-API minimum interval**: the first request does not wait, the time spent on the request itself counts toward the interval, and switching to another API in fallback mode is immediate. Same rate-limit protection per API, much faster fallback.
- **Repeated CNPJs in the same execution are queried only once** (per strategy/API); each output item receives its own copy of the data.
- When a **Specific API** fails, the node throws `NodeApiError` instead of `ApplicationError`, preserving the HTTP status and n8n's friendly message; the failing API and original error go in the description.

## Fixed

- **CNPJ.ws phone normalization** ([#1](https://github.com/dssiqueira/n8n-nodes-cnpj-hub/issues/1)): `contato.telefone` no longer contains `"undefined"` (e.g. `"11undefined"`) when only the area code or only the number is returned.
- **Codex metadata** ([#2](https://github.com/dssiqueira/n8n-nodes-cnpj-hub/issues/2)): `CNPJHUB.node.json` uses the package name (`n8n-nodes-cnpj-hub`) instead of the reserved `n8n-nodes-base` prefix. Documentation URL fixed.
- **Build**: `setTimeout` replaced by `sleep` from `n8n-workflow` (`tsc` was failing).

## Documentation

- Updated README-pt.md with OpenCNPJ information
- Enhanced API descriptions for clarity
- Fixed contact information formatting

## Breaking Changes

None in the output format. Behavior notes for users coming from 0.1.0:

- CNPJs with wrong check digits are now rejected before any API call (`Invalid CNPJ: ...`). Before, they were sent to the APIs and failed there.
- The codex `node` field is metadata only; the workflow node type (`n8n-nodes-cnpj-hub.cnpjhub`) did not change.

## Migration Guide

No migration needed. All existing workflows continue to work without changes.
